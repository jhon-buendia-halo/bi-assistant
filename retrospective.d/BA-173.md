### What went well
- Moving the BA-172 entries into fragments made this PR's own merge the end-to-end test: the first collection happens on the real release workflow, not only in a dry run.
- The collector and the checker share one module (`scripts/fragments.py`), so a fragment that passes CI is one the release can collect.
- The negative cases (no fragment, a direct edit, a malformed fragment) were each run and saved, not only the passing case.

### What went wrong
- The first version of the branch check diffed `base...HEAD`, so it ignored uncommitted and untracked files and reported a clean branch as broken when run locally. It was caught only by running it before committing.
- The `workflow-steps` mod keyed steps 10 and 11 on `changelog.md` and `retrospective.md`; a convention change that moves where a step writes also changes the mod, and that was found by grepping, not by a check.

### What to do differently
- A check meant to run locally compares the working tree with the merge base (`git diff <merge-base>` plus untracked files), not `base...HEAD`.
- When a convention changes which file a workflow step writes, grep `.claude/mods/` for that file name in the same story.
