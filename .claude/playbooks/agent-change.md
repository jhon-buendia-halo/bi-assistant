### Agent change

A new agent, or a change to what an agent receives: its prompt, skills, tools, context blocks or model routing. Each step below fills the workflow step named in brackets.

1. **[Understand]** Name what the agent receives that changes. Hash `getInstructions()` and its tool list on the base and on the branch: equal hashes mean the evals need not run ([lessons.md](../../lessons.md), *Evals and agents*).
2. **[Understand]** Measure before designing: prompt sizes from the compiled agent (`getInstructions()`), not from the source text ([lessons.md](../../lessons.md), *Process and hand-over*).
3. **[Implement]** **Query inspector.** Every agent that answers from data shows its evidence the same way (existing agents, new ones and user agents alike). Each figure in an answer links to the query behind it. Each query is explained step by step in business words, with the rows at each stage and a coverage label (whole table, top N after ranking, sample, partial result), and any `LIMIT` or row cap is explained in plain words. The full result is one click away. Build it once in the shared layer (the `run_readonly_sql` bridge, the captured tool data, the answer view), never in one agent's prompt or screen, so an agent gets it by using the dataset tools. When you add or change an agent, check that its answers pass through that layer; an agent that cannot use it says why in its spec. Rules: [agent-answers](../../specs/capabilities/agent-answers/spec.md), *Query inspector*. A host turns it on with the answer view's `queryInspector` input and provides `QUERY_EVIDENCE_API`; today the hosts are the Run panel and the run detail page, for every workflow run whose answer ran queries, plus past chats and Try it. Connect another host to it rather than add another way of showing an agent's queries.
4. **[Implement]** A new agent follows the backend code rules in [`workflow-implement`](../skills/workflow-implement/SKILL.md) (its file, its registration, its `agents.md` entry, `resolveAgentModel()`). A new instruction goes last in the agent's instructions and fires on a cue the request itself carries ([lessons.md](../../lessons.md), *Evals and agents*).
5. **[Checks]** When step 1 says the evals run: [`verify`](../skills/verify/SKILL.md), *Evals* (a fresh copy of the data dir per run, the model agreed with the user, base against branch, at least 3 runs per case per build). For a failed case, read its `toolCalls` before touching code.

**Reply:** what the agent receives now that it did not before, and each eval case's pass rate on the base and on the branch.
