# Changelog

Running log of every meaningful change, newest first. See *Logging convention* and *Evidence convention* in [CLAUDE.md](CLAUDE.md). Release versions come from Conventional Commits (`version-on-merge.yml`); this file records what shipped and links to the evidence.

## 2026-10-02 (BA-86)

### Added
- **Logical query layer — the assistant reasons over abstract entities, never a physical table or dialect word** (roadmap 1.2.2 / [BA-86](https://halo-powered.atlassian.net/browse/BA-86), ADR-0007, now Accepted). New `backend/src/modules/data-models/session-model.ts`: `composeSessionModel` unions a session's current dataset models (deduping an identically-bound entity across datasets, qualifying `<datasetSlug>__<entity>` when the same name binds different tables) and `renderModelBlock` renders the ONE system block — entities, attributes with roles/types/relationship arrows/sample values, and metric formulas — that replaces the old dataset/entity orientation, join-hint and curated-metrics blocks.
- New `backend/src/modules/data-models/query/`: `logical-query.ts` (the `LogicalQuery` Zod schema — `from`, `select`, portable `where`, `group_by`, `order_by`, `limit`, `joins[]` — and `resolveLogicalQuery`, which builds the join graph, auto-joins a dotted attribute reference along its one declared relationship path, rejects an ambiguous or absent path, and auto-fills `group_by` when plain attributes and aggregations are mixed) and `compile-sql.ts` (`compileLogicalQuery`, one compiler for Postgres, Databricks SQL and SQLite — identifier quoting, metrics incl. `ratio`, date buckets, literal escaping, and a fan-out guard against a one-to-many join feeding a plain, unaggregated attribute).
- New `mastra/tools/model.tools.ts` replaces `datasetTools` on the `assistant` agent: `list_entities`, `describe_entity`, `query_entities` (compiles and runs a `LogicalQuery`, returning a structured `{code, message, path}` error — no database call — on an unknown reference or unresolved path), `sample_records`, and `run_raw_sql` (the flagged last resort; every result it produces is marked `outsideModel: true`). `assistant.agent.ts`'s instructions were rewritten to the model vocabulary — no catalog, schema, table, Databricks, PostgreSQL, SQLite or "dialect" anywhere — and `assistant.instructions.ts` splits them into their own module so a Jest spec can assert this without loading `@mastra/core/agent`.
- New agents `query-fixer` (one automatic repair attempt inside `query_entities` for an `unknown_attribute`/`unknown_metric`/`ambiguous_path` issue, before the assistant ever sees an error) and `query-verifier` (careful mode's independent second opinion, re-deriving a `LogicalQuery` from the rendered model block alone); both replace `sql-verifier` (removed) at the logical level. `sql-fixer` is unchanged and keeps repairing *runtime* errors on already-compiled SQL. `SessionsService.crossCheckAnswer` now compiles and runs the verifier's logical query instead of raw SQL text.
- New `assistant-legacy` agent (`assistant-legacy.agent.ts`) is a frozen copy of the pre-change assistant (old instructions + `datasetTools`), registered only so the eval harness has a real `legacy` path to compare against. `mastra/evals/assistant.evals.ts`'s `runAssistantEvalCase`/`runAssistantEvals` take a `{ path?: 'model' | 'legacy', metricsBlock? }` option; each `AssistantEvalCaseResult` now carries `path` and `outsideModel` (true when the run called `run_raw_sql`). `EvalRunView` carries `path` (default `model`) and `outsideModelCount`; `POST /agents/:key/evals/run` accepts `{ path }`; the CLI (`npm run evals:assistant` in `backend/`) reads `EVAL_PATH=legacy|model`. The eval run's markdown report and the Agents → Evals tab both show the path and the outside-the-model count.
- `POST /datasets/:name/model/compile` (pure — resolves and compiles a `LogicalQuery` against the dataset's current model with no database call, `dialect` optional, defaults `postgres`) and `POST /datasets/:name/model/query` (compiles for the datasource's own kind — `rest` as sqlite — and runs it) on `DataModelsController`, for the 1.2.3 editor and for e2e. `DataModelsService.getCurrentModels` fetches the current `DataModel` for a set of datasets in one call.

### Changed
- `ToolDataRecord`/`ChatMessage` gain `logicalQuery` (the `query_entities` call's own JSON input, alongside the compiled SQL already in `input`), `outsideModel`, and `modelVersions` (the `{dataset, version}[]` the turn's rendered model block was built from, for provenance) fields. `turn-data.ts`'s `toolDataRecord` and `SQL_RUN_TOOLS` now recognise both the legacy (`run_readonly_sql`, `sample_rows`) and logical (`query_entities`, `sample_records`, `run_raw_sql`) tool names, so cross-checking, the verified-query badge and a visual's `refresh` endpoint work on either path.
- `frontend/e2e/agents.spec.ts` and `gherkin.md`'s *Feature: Agents* updated for the new tool/agent names (`query_entities` replaces `run_readonly_sql` in the Tools tab; `query-verifier` replaces `sql-verifier` in the agent list) — see the impact table appended to [docs/plans/ba-86-logical-query-layer.md](docs/plans/ba-86-logical-query-layer.md).
- `gherkin.md`'s *Feature: Data model* gains two scenarios: compiling a logical query returns dialect SQL without a database call, and an unknown attribute or an undeclared relationship is rejected before one.

### Removed
- `mastra/agents/sql-verifier.agent.ts` and the `sql-verifier` registration — nothing else depended on it once `query-verifier` took over careful mode.

Evidence: [evidence/1.2.2/](evidence/1.2.2/) — backend e2e 13/13 (`e2e-results.txt`, the two new scenarios plus the 1.2.1 suite unaffected), backend unit 872/872 (`unit-results.txt`), the real rendered model block and golden SQL for all three dialects from the World Cup fixture (`sample-model-block-and-golden-sql.txt`), and `README.md` with the two `EVAL_PATH` commands to run the real `model` vs `legacy` comparison once an LLM key is configured (none is available in this environment; the path/agent-selection/counter plumbing is unit-tested with a stubbed agent instead).

## 2026-10-01 (BA-85)

### Added
- **Data model DSL, bootstrap and versions** (roadmap 1.2.1 / [BA-85](https://halo-powered.atlassian.net/browse/BA-85), ADR-0006): every dataset now owns a storage-neutral data model — entities with typed attributes (roles, nested paths, sample values), relationships with explicit cardinality and provenance, metrics in a portable aggregation core with an `expressions.sql` escape hatch, and `bindings` per datasource kind (`sql`, `rest`; `mongo`/`file` accepted by the schema, no adapter yet). New `backend/src/modules/data-models/`: Zod schema with exported JSON Schema (`GET /data-models/schema.json`), YAML parse/serialize with line-and-column errors, semantic validation (unique names, resolvable targets, binding columns that exist in the snapshot), `data_models` collection with immutable versions and a current pointer (`GET/PUT /datasets/:name/model`, `…/versions/:v`, `…/revert`, `…/bootstrap`, `…/drift`, `…/resolve`), and logical references (`entity`, `entity.attribute`, `metric:name`, `rel:from->to`) resolved by `resolveRef` for the Knowledge Store (1.3.2).
- v1 is bootstrapped automatically from the physical snapshot on dataset save and, at startup, for every existing dataset without a model (per-dataset errors are logged and skipped). A re-save merges newly included tables into a new version and records a drift report for removed or changed attributes; user edits are never overwritten.
- Research and decision record for the whole epic in [docs/plans/ba-2-data-model-dsl-alternatives.md](docs/plans/ba-2-data-model-dsl-alternatives.md): three alternatives compared, the logical query layer (ADR-0007, story 1.2.2) and the Knowledge Store contract (1.3). Stories BA-85/86/87 created in Jira.

### Changed
- `MetricsService` mirrors every panel write into each current model that binds the metric's table (`syncMetric` / `removeMetric`); the shared `metrics` store stays the panel's editor of record until 1.2.3, so the panel behaves exactly as before. `DatasetsService.delete` cascades to the model.
- Backend e2e harness: `backend/test/data-models.e2e-spec.ts` boots a focused module set instead of `AppModule` (Mastra's ESM-only dependencies cannot load under Jest's CommonJS runtime) and uses `import request from 'supertest'`.

Evidence: [evidence/1.2.1/](evidence/1.2.1/) — backend e2e 10/10 + unit 835/835, Playwright Electron 20/20 (`frontend-e2e-results.txt`), frontend build, a live bootstrapped World Cup model (`world-cup-core-model-v1.yaml`), API responses for bootstrap / invalid PUT / valid PUT / resolve / drift (`api-responses.json`), and the published JSON Schema. Known pre-existing failure outside this change: frontend unit test *App › keyboard resizing from the separator* (frontend tree identical to main).
