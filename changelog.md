# Changelog

Running log of every meaningful change, newest first. See *Logging convention* and *Evidence convention* in [CLAUDE.md](CLAUDE.md). Release versions come from Conventional Commits (`version-on-merge.yml`); this file records what shipped and links to the evidence.

## 2026-10-02 (BA-87)

### Added
- **Data model editing, versioning and export** (roadmap 1.2.3 / [BA-87](https://halo-powered.atlassian.net/browse/BA-87), builds on ADR-0006): analysts curate each dataset's data model inside the app instead of only through bootstrap. Backend additions on `backend/src/modules/data-models/`: `GET …/model/export[?version=N]` (YAML file download, `Content-Disposition` named `<dataset-slug>.model.v<N>.yaml`), `POST …/model/import` (same validation as the existing `PUT`, recorded as `source: 'import'`), `POST …/model/serialize` (the one YAML writer, exposed so the frontend's structured forms never need their own), `GET …/model/versions` (the full version history for the Versions tab — `GET …/model` only ever returned the current one), and model-scoped metrics CRUD (`GET/POST/PUT/DELETE …/model/metrics[/:name]`, `GET …/model/metrics/candidates` via a new `ModelMetricCandidatesController`) — the metrics panel's new editor of record, validated through the same `validateDataModel` every YAML save goes through.
- New frontend feature `frontend/src/app/features/data-model/`: `data-model-api.service.ts` (typed client for every endpoint above plus 1.2.1's), `data-model-view` (header with version badge, drift pill, Export/Import/Bootstrap, and Overview/YAML/Versions/Metrics tabs), `model-yaml-editor` (line-numbered textarea, clickable line/col error list), `model-versions` (list, revert, a two-version diff via the new `shared/utils/line-diff.ts`), `entity-editor` (structured entity/attribute/relationship forms that serialize through `/serialize` then save through `PUT`), and `model-metrics-panel` (create/edit/delete metrics directly on the model, with a single-condition `where` builder and candidate promotion). `dataset-list` gets a "Data model" row action; `app.ts`/`app.html` gain the `'dataset-model'` main view.

### Changed
- `DataModelsService.syncMetric` / `removeMetric` (the legacy metrics-panel mirror): the merge rule flips from "the legacy store always wins" to "the model wins for any metric name it manages itself" — tracked by a new `DataModelDoc.localMetricNames` field, written by the model-metrics API. A legacy `/metrics` write or delete of a name the model already manages directly is now skipped on that model instead of overwriting or deleting it; the mirror is otherwise unchanged (still adds metrics the model is missing).
- `features/datasets/components/catalog-browser`: the inline metrics panel is replaced with a note pointing at the dataset's data model after saving.

### Removed
- `frontend/src/app/features/datasets/components/metrics-panel/`, `services/metrics-api.service.ts(.spec.ts)`, `models/metric.model.ts` — superseded by `features/data-model/components/model-metrics-panel`. No Playwright spec referenced their test ids (confirmed by search), so nothing else needed updating.

### Fixed
A code review of the diff above, run after the orchestrator's first full Playwright pass (25/27, both `data-model-editing.spec.ts` failures below), found 12 issues; all are fixed and covered by new/updated tests:
- **Metrics grounding regression**: `MetricsService.definitionBlock` (the governed-metrics prompt block) still read the legacy `metrics` store exclusively, so a model-metrics-panel edit or delete never reached answers. New `DataModelsService.metricsBoundToEntities`/`promotedVerifiedQueryIds` let it read the current data model for any table a model binds (portable `agg/of/where` rendered as text, `expressions.sql` verbatim) and fall back to the legacy store only for tables no model binds.
- **`<select>` showed the wrong option** in `entity-editor.html` and `model-metrics-panel.html`: `[value]` on the `<select>` alone does not reliably select the matching `@for`-generated `<option>` in this Angular/Tailwind setup — every select rendered its first option regardless of the bound value. Fixed by adding `[selected]` per `<option>`, the pattern `catalog-browser.html` already used. This was the root cause of the "changes a relationship's cardinality" Playwright failure: the test read the (wrongly-displayed) current value, picked "a different one," and silently picked the value the data already had, so nothing was dirty and Save stayed disabled.
- **Playwright `download` event / `Content-Disposition` header**: the Electron renderer does not surface Playwright's `download` event (same constraint `agents.spec.ts`'s report-download test already works around), so the export scenario now asserts the `GET …/model/export` network response directly. Separately, that response's `Content-Disposition` is unreadable to renderer JS anyway — `app.enableCors()` exposes no custom headers, and the call is cross-origin under `file://` — so `data-model-view.ts` now builds the export filename client-side (`slugifyDatasetName`, mirroring the backend's own slug logic) instead of reading the header.
- **`deleteModelMetric` saved without validation**: it now runs through the same `validateDataModel` create/update already use, so deleting a metric another metric's `ratio` still references is rejected with a clear error instead of leaving a dangling reference.
- **Deleted metrics could come back**: a new `DataModelDoc.deletedMetricNames` tombstone is honoured by `rebootstrap`, `mergeSnapshot` and the legacy `syncMetric` mirror, so a name removed through the model-metrics panel stays removed even though the legacy store may still have a same-named row; recreating the name clears the tombstone.
- **A metric shape the form cannot represent** (a compound `where` tree, or both `agg` and `expressions.sql` at once) now opens the metrics-panel form read-only with a note ("advanced definition — edit in the YAML tab") instead of silently dropping the part it cannot load on save.
- **Promotion-candidate scoping**: `MetricsService.candidates`/`candidatesForDataset` now treat a verified query as promoted when *any* current model has a metric with that `sourceVerifiedQueryId` (not just the legacy store or a name match on the one dataset asked about), and the filter runs before the 12-candidate slice so a promoted pair never silently displaces a real one off the page.
- **Overview tab now shows relationships (with cardinality) and metrics**, not just counts — needed for the cardinality-change scenario to verify the result without re-opening the entity form, and for the "sees its bootstrapped entities, relationships and metrics" scenario to assert on real content.
- **YAML editor**: the textarea no longer soft-wraps (`white-space: pre`, `wrap="off"`), which was breaking the 1:1 mapping between gutter line numbers and rendered rows for any long line; an error with no column now renders "line 12" instead of a bare "12:".
- **Wording/small fixes**: `exportYaml`'s doc comment said `POST`, corrected to `GET`; the unused, misleadingly-named `relativeTime` (always rendered an absolute timestamp) is removed from `data-model-view.ts` and renamed to `formattedTime` in `model-versions.ts`; the drift pill now counts only `removed`/`changed` attributes, matching its own tooltip; `POST …/model/serialize` now validates the body against the full Zod schema and returns 400 for a malformed one instead of silently defaulting missing arrays to empty.
- Roadmap 1.2.3's acceptance line, this brief and `gherkin.md`'s export/import scenario now say "re-imports identically **apart from the version header**" — `appendVersion` always rewrites the `model`/`version` lines to the new version's own identity, so a byte-identical re-import was never literally true; every entity, relationship and metric still matches exactly.

## 2026-10-01 (BA-85)

### Added
- **Data model DSL, bootstrap and versions** (roadmap 1.2.1 / [BA-85](https://halo-powered.atlassian.net/browse/BA-85), ADR-0006): every dataset now owns a storage-neutral data model — entities with typed attributes (roles, nested paths, sample values), relationships with explicit cardinality and provenance, metrics in a portable aggregation core with an `expressions.sql` escape hatch, and `bindings` per datasource kind (`sql`, `rest`; `mongo`/`file` accepted by the schema, no adapter yet). New `backend/src/modules/data-models/`: Zod schema with exported JSON Schema (`GET /data-models/schema.json`), YAML parse/serialize with line-and-column errors, semantic validation (unique names, resolvable targets, binding columns that exist in the snapshot), `data_models` collection with immutable versions and a current pointer (`GET/PUT /datasets/:name/model`, `…/versions/:v`, `…/revert`, `…/bootstrap`, `…/drift`, `…/resolve`), and logical references (`entity`, `entity.attribute`, `metric:name`, `rel:from->to`) resolved by `resolveRef` for the Knowledge Store (1.3.2).
- v1 is bootstrapped automatically from the physical snapshot on dataset save and, at startup, for every existing dataset without a model (per-dataset errors are logged and skipped). A re-save merges newly included tables into a new version and records a drift report for removed or changed attributes; user edits are never overwritten.
- Research and decision record for the whole epic in [docs/plans/ba-2-data-model-dsl-alternatives.md](docs/plans/ba-2-data-model-dsl-alternatives.md): three alternatives compared, the logical query layer (ADR-0007, story 1.2.2) and the Knowledge Store contract (1.3). Stories BA-85/86/87 created in Jira.

### Changed
- `MetricsService` mirrors every panel write into each current model that binds the metric's table (`syncMetric` / `removeMetric`); the shared `metrics` store stays the panel's editor of record until 1.2.3, so the panel behaves exactly as before. `DatasetsService.delete` cascades to the model.
- Backend e2e harness: `backend/test/data-models.e2e-spec.ts` boots a focused module set instead of `AppModule` (Mastra's ESM-only dependencies cannot load under Jest's CommonJS runtime) and uses `import request from 'supertest'`.

Evidence: [evidence/1.2.1/](evidence/1.2.1/) — backend e2e 10/10 + unit 835/835, Playwright Electron 20/20 (`frontend-e2e-results.txt`), frontend build, a live bootstrapped World Cup model (`world-cup-core-model-v1.yaml`), API responses for bootstrap / invalid PUT / valid PUT / resolve / drift (`api-responses.json`), and the published JSON Schema. Known pre-existing failure outside this change: frontend unit test *App › keyboard resizing from the separator* (frontend tree identical to main).
