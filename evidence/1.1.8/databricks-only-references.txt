Databricks references: world-cup-databricks-only.json (BA-186, 2026-10-13)
The ten Databricks-only World Cup questions (agents-evals R145 to R147). Nine have a reference query; the
browse-only question has none, by design. None was executed on a Databricks warehouse: that run is the VDI
validation (docs/evals/databricks-vdi.md). Every line below is "not executed — VDI".
The references below are as written in the set file, with the canonical catalog `evals`; where one runs (the
result-set match, eval:validate) its `evals`. is rewritten to the selected datasets' catalog (agents-evals R148).

How each reference was checked without a warehouse
- Static (unit test backend/src/mastra/evals/databricks-references.spec.ts, agents-evals R144): the Step 1b
  dialect check finds nothing for databricks (R74); no '::' cast and no PostgreSQL-only function (age,
  to_char, generate_series, string_to_array); every table reference has 3 parts, is `evals`.world_cup.<table>
  with the catalog backticked, and names a required table of the sample. The same test passes on every
  Databricks reference of every set (126 on 2026-10-13: the 9 here and the 117 the dialect work added).
- PostgreSQL: the same logic written in PostgreSQL ran on ba9_world_cup_dbx_only, a copy of the World Cup
  seed (001_world_cup.sql) on the compose server; its rows are the expected answer.
- Parse and proxy: sqlglot 30.22.0 parses the reference with its Databricks dialect; the parsed statement,
  transpiled to DuckDB 1.5.6, runs on DuckDB tables that the loader's own SQL created and filled (the World
  Cup dry run, see databricks-loader-sql-check.txt). Its rows are compared with PostgreSQL's as the result-set
  match compares them (any row order, 6 significant figures). One transpile needed a workaround: sqlglot
  expands months_between for DuckDB without parentheses, so the call is wrapped before transpiling.

  PostgreSQL equivalent: SELECT p.full_name, date_part('year', age(m.kicked_off_at::date, p.date_of_birth)) AS age_in_years FROM world_cup.goals g JOIN world_cup.matches m ON m.id = g.match_id JOIN world_cup.tournaments t ON t.id = m.tournament_id JOIN world_cup.players p ON p.id = g.scorer_player_id WHERE t.tournament_year = 2022 AND g.goal_type <> 'own_goal' ORDER BY age(m.kicked_off_at::date, p.date_of_birth) LIMIT 1
  PostgreSQL rows (1): Josko Gvardiol, 20
