History: the orchestrator's first full-suite run (frontend `npm run test:e2e`)
reported 25/27 passing with scenarios 5 and 7 failing. Code review identified
the root causes (see docs/plans/ba-87-model-editing.md):
  - #5 (cardinality): entity-editor.html's <select [value]> bound the
    element but never marked an <option> [selected], so every select in
    the entity/metrics forms rendered its first option regardless of the
    real value — Playwright's selectOption() picked the same underlying
    value the model already had, so nothing was actually dirty and Save
    stayed disabled. Fixed by adding [selected] per <option>, matching
    catalog-browser.html's existing working pattern.
  - #7 (export/import): Playwright's `download` event is not wired through
    the Electron renderer (same constraint already noted in
    agents.spec.ts's Markdown-report download test); the test now asserts
    the `GET .../model/export` network response directly and feeds its
    body into the import step. The export filename is also now built
    client-side (`slugifyDatasetName`) rather than read from
    Content-Disposition, which is unreadable cross-origin under Electron's
    file:// -> http://localhost:3000 call without CORS exposedHeaders.

Both fixes (and ten other code-review findings spanning backend metrics
grounding, delete validation/tombstoning, promotion-candidate scoping,
Overview relationship/metric display, YAML editor line-wrap/highlight
rendering, and wording corrections) are applied; this run reflects the
fixed state, 7/7 green.
