LLM call detail with its context window

see what filled a call's context window, and how much of it the app put there versus what came from the user, so prompts and context can be trimmed with evidence.

In progress

Scope

  • clicking a row opens the call's page (Monitoring stays current
  • a Monitoring back control returns to the table with its filters and page kept): the call's facts (agent, model, provider, session, started, duration, time to first token, finish reason, tokens in / out with cache reads and writes, reasoning tokens, estimated cost, error)
  • the context window: a stacked bar of the estimated tokens of seven boxes, against the model's context limit when known, then the seven boxes in order, each tagged by who owns it, with its estimated tokens and share, expandable to the exact text: System prompt (US Health), Skill injection (US Health), Tools injection (US Health), Chat history (Custom), Dataset (Custom), User prompt (Custom), Tool calls and results in this run (Custom)
  • then the run's model steps (tokens, finish reason, duration). GET /monitoring/llm-calls/:id.

Out of scope: exact per-box token counts (estimates, scaled to the real input tokens of the run's largest step); comparing calls; replaying a call.

Acceptance

  • a chat turn's call page shows the seven boxes with text matching what was sent (system prompt, the <available_skills> list, the tool definitions, the earlier turns, the session's dataset blocks, the question, the SQL run and its rows)
  • the box estimates add up to the step's real input tokens
  • Back keeps the filters and page
  • unit tests, the build and the impacted E2E green.
