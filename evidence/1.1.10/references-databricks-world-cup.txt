How each reference was checked without a warehouse
- Written from the PostgreSQL reference as R206 says: every table `evals`.world_cup.<table>, the ::numeric cast dropped
  before a division (whole numbers divide into a DOUBLE on Databricks), the alias match renamed m.
- Static (static-checks.ts, with the repository's check modules, the checks of databricks-references.spec.ts):
  dialectProblem(sql, 'databricks') finds nothing (R118); no '::' cast, no age/to_char/generate_series/
  string_to_array, no FILTER; every table reference is `evals`.world_cup.<table> with the catalog backticked and a
  required table of the sample; the reference reads the same tables as the PostgreSQL one. The Jest suite
  databricks-references.spec.ts (R188, also rewritten to two other catalogs, R192) passes on the file.
- Parse: sqlglot 30.23.0 parses it with its Databricks dialect, raising on any error.
- Proxy run: the parsed statement, transpiled by sqlglot to DuckDB 1.5.6, runs on DuckDB tables in
  catalog evals, schema world_cup (14 relations), created with the PostgreSQL column types of the isolated
  database and loaded from the same dump (backend/scripts/worldcup-rest-api/data). DuckDB, like Databricks, divides
  whole numbers into a fraction. Its rows are compared with the PostgreSQL reference's rows as the result-set match
  compares them. This shows the translation keeps the meaning; it does not show the warehouse accepts the text.
