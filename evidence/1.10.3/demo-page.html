LLM configuration · roadmap 1.10.3

GitHub Copilot as an LLM provider

a developer with a GitHub Copilot seat picks GitHub Copilot in Settings → LLM Configuration, tests and saves, and every agent then runs on their own seat, with no API key and no extra spend.

Done

What shipped

  • 2026-11-10 · Added

    GitHub Copilot as an LLM provider (epic BA-159, roadmap 1.10.3, ADR-0037, specs/epics/BA-159/spec.md, llm-settings R55–R66).
    • Settings → LLM Configuration offers GitHub Copilot: every agent runs on the developer's own Copilot seat, signed in with the GitHub login already on the machine (GitHub CLI, Copilot CLI or app). No API key, base URL or API style; the form shows who is signed in, or how to sign in. Model auto lets Copilot choose; Load models lists the seat's models (none on a Free seat). Test connection, real streaming, reasoning effort by model name, and <model> · GitHub Copilot in the composer, the agent page and the catalogue. Saving Copilot removes any stored API key.
    • Backend: the official @github/copilot-sdk 1.0.30 (pinned) drives one local Copilot runtime per process. An AI SDK model over it declares the agents' tools without handlers, so Mastra keeps the tool loop; Copilot's built-in tools stay off and the system prompt is replaced. New GET /llm/copilot/status; POST /llm/models and the effort levels take the provider (api.md, agents.md, data-model.md, ui.md, tech-stack.md).
    • R66, found by the evals: when the model writes a tool's arguments as its message instead of calling the tool, the message is never shown and the model is asked once, in the same session, to make the call.
    • Evidence: evidence/1.10.3/: tests.md, demo.webm, evals.md (custom endpoint 100%; GitHub Copilot on a Free seat 32/36 after R66, the rest answer quality of the auto-routed model, documented), unit-baseline.txt. E2E llm-copilot.spec.ts runs against a stub of the Copilot runtime written from a recorded trace of the real one. Desktop not run; the installers and the npm package are story 1.10.4.

Scope

  • a fifth provider copilot ("GitHub Copilot") on the official Copilot SDK (ADR-0037): the backend starts one Copilot runtime and builds an AI SDK model whose tools are declared to Copilot without handlers, so Mastra keeps the tool loop, built-in Copilot tools are off and the system prompt is replaced
  • sign-in reuses the GitHub login already on the machine (gh CLI or Copilot CLI/app), and the form shows who is signed in or how to sign in
  • no API key or base URL
  • model defaults to auto (Copilot picks), Load models lists the seat's models, any typed name is accepted
  • Test connection runs the structured-output probe through the adapter
  • answers stream word by word
  • reasoning effort by model name, none for auto
  • abandoned Copilot sessions time out and the turn's abort signal stops them
  • the composer chip, the agent page and the catalogue name the provider
  • llm-settings, api.md, data-model, agents.md, ui.md, tech-stack, glossary and architecture (ADR-0037) updated
  • Gherkin for the new flows.

Out of scope: a Sign in with GitHub button or pasted GitHub tokens; Copilot BYOK; the eval CLI's EVAL_LLM_PROVIDER=copilot; per-agent providers; bundling the runtime in installers (1.10.4).

Acceptance

  • with a signed-in seat, Settings → LLM Configuration offers GitHub Copilot, shows the GitHub login, tests and saves with model auto
  • a chat turn on World Cup Core answers with real SQL tool calls and streams text
  • Load models answers (an empty list on a Free seat reads as Copilot choosing)
  • with no GitHub login the test reports how to sign in and nothing is saved
  • switching back to another provider still needs that provider's key
  • unit tests for the adapter (tool loop, pending tool results, structured output, streaming, timeout and abort), the settings rules and the form
  • check-specs, lint, builds and the LLM settings Playwright specs green.
